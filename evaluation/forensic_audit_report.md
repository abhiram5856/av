# Forensic Evaluation Audit

## 1. Metric Inconsistency Analysis

A critical metric discrepancy was identified between historical metrics (80.80% Field Accuracy) and recently observed outputs in `evaluation/baseline_field_metrics.json` (74.40% Field Accuracy). 

A forensic audit of the repository's git history, evaluation scripts (`run_final_eval.py`, `run_hybrid_field_domain.py`), and historical rejection notes (`experiments/archive/candidate_v3_rejection_note.md`) reveals the following:

- **Source of 80.80% / 67.42%**: These are the true, formally validated metrics for the production model (`nova_mobilenet_v3_34_classes.pth`). They were generated using the correct, authoritative preprocessing pipeline: `Resize(256) -> CenterCrop(224) -> ToTensor() -> Normalize()`. This is explicitly documented in the `candidate_v3_rejection_note.md` as the authoritative baseline, and hardcoded in `run_hybrid_field_domain.py` as the "CURRENT PRODUCTION" delta comparison base.
- **Source of 74.40% / 46.60%**: This result was found in `evaluation/baseline_field_metrics.json`. The forensic evidence points to this being a stale artifact generated from an earlier iteration of the evaluation script (likely using `Resize((224, 224))` directly instead of a center crop, squashing aspect ratios, or a different validation subset before the final `clean_test_split.json` was frozen).
