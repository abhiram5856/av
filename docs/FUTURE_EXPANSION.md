# Future Expansion Strategies

This document reserves architecture nodes for planned future capabilities of Zenith AgriBot.

## 1. CNN Disease Prediction Integration
**Goal**: Accept image analysis results as context.
**Architecture**: The `/api/chat` payload accepts a `DiseasePrediction` object in the `UserQuery` payload. The `PromptBuilder` checks for `query.disease_context` and prepends the prediction data natively into the system prompt.

## 2. Voice Chat (STT / TTS)
**Goal**: Allow illiterate or remote farmers to interact via voice.
**Architecture**: 
- **STT**: `audio_processor` module transcribes voice to text. Output is fed to the standard `translation` -> `chat_engine` flow.
- **TTS**: `ChatResponse` text is fed to a `tts_engine` (e.g., Coqui TTS or Bark) to generate an audio stream back to the user.

## 3. Weather & Government APIs
**Goal**: Fetch real-time local weather or scheme data.
**Architecture**: Introduce a `tools/` or `plugins/` directory. If the retriever detects low confidence on dynamic data, the engine routes the query to a `WeatherPlugin` instead of the standard vector store.

## 4. Farmer Profiles
**Goal**: Personalized context (e.g., location, crop type).
**Architecture**: Expand `Conversation` and `Session` metadata to include `FarmerProfile`. Inject `FarmerProfile` into `PromptBuilder` automatically.

## 5. GradCAM Explainability
**Goal**: Explain *why* the CNN predicted a disease.
**Architecture**: Create an `/api/explain` route that accepts an image and returns a heat map, coupled with a descriptive text generated by the LLM based on the bounding boxes.
